# Deploying the Pilot on Render

Render hosts the API + web as Docker services and provides the managed
PostgreSQL. Total time: ~20 minutes. Cost: two Starter services + Basic
Postgres (or the free DB tier for a short demo).

## 1. Create the Blueprint

1. Push this repo to your GitHub (already done) and log in to render.com.
2. **New → Blueprint**, pick the `simboni/ERP` repo and this branch.
3. Render reads `render.yaml` and proposes: `jenga-db` (Postgres 16),
   `jenga-api`, `jenga-web`. Approve. The first API deploy will fail on
   migrations — expected, the DB roles don't exist yet. Continue.

## 2. Bootstrap the database roles (once)

From the `jenga-db` page → **Connect → External Connection** copy the psql
command, then locally (or in Render's shell):

```bash
psql "<owner-connection-string>" \
  -v app_pw="'$(openssl rand -hex 24)'" \
  -v worker_pw="'$(openssl rand -hex 24)'" \
  -f db/bootstrap-managed.sql
```

Keep the two generated passwords.

## 3. Set the environment variables

On **jenga-api** (Environment tab):

| Key | Value |
|---|---|
| `ADMIN_DB_URL` | the owner connection string (internal URL) |
| `APP_DB_URL` | same URL but user `jenga_app` + the app password |
| `WORKER_DB_URL` | same URL but user `jenga_worker` + the worker password |
| `WEB_ORIGINS` | `https://jenga-web-XXXX.onrender.com` (the web service URL) |

On **jenga-web**:

| Key | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | `https://jenga-api-XXXX.onrender.com` |

`JWT_SECRET` and `DATA_ENCRYPTION_KEY` were auto-generated by the Blueprint.

## 4. Redeploy and verify

1. **Manual Deploy** on jenga-api — the pre-deploy migration job applies
   all `db/migrations/*.sql`, then the service starts. Check
   `https://jenga-api-XXXX.onrender.com/health` → `{"status":"ok"}`.
2. Manual Deploy on jenga-web (rebuild picks up the API URL).
3. Open the web URL, sign up, and run the demo loop: seed accounts happens
   on first invoice; issue → eTIMS sandbox control number appears.

## Notes

- **Providers stay in sandbox** (`FISCAL_PROVIDER`/`PAYMENT_PROVIDER`
  unset = sandbox) until KRA/Safaricom credentials exist — flip them via
  env vars when they do (see `.env.example`).
- M-Pesa webhooks: point Daraja's confirmation URL at
  `https://jenga-api-XXXX.onrender.com/webhooks/mpesa/c2b/confirmation`
  when you register the real shortcode.
- The free Postgres tier expires after 30 days — fine for a demo, use
  Basic for the pilot. Production remains AWS af-south-1 per
  `docs/deploy.md`.
- Never point `APP_DB_URL` at the owner user: the RLS tenant wall depends
  on the runtime role owning nothing (04-architecture.md §3).
